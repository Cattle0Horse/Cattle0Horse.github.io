# Skill 编写的六个常见问题

Skill 的目标是提高 Agent 行为的可预测性：让执行过程稳定，让结果保留任务所需的变化。而不是让 Agent 每次的输出都一模一样。例如，头脑风暴可以产生不同创意，但发散、筛选和评估的流程应当一致。

## 1. 过早收工：完成标准模糊

“抽查几条，没问题就继续”缺少明确的检查范围和通过条件，容易让 Agent 提前结束。

**改进**：将完成标准写成可核验的条件，例如检查首尾各三条字幕与音频是否对齐；能用验收脚本验证的步骤，以脚本结果为准。

## 2. 重复：同一规则多处出现

重复说明会增加维护成本、消耗上下文，还可能让某条规则获得过高权重。修改时遗漏一处，就可能产生冲突。

**改进**：每条规则只在一个权威位置完整定义，其他位置通过引用关联。

## 3. 沉积：旧方案残留

方案更新后，旧术语、参数和文件名未同步清理，会让新旧说明相互矛盾。

**改进**：替换方案时，全局检索相关表述，统一更新或删除过时内容。

## 4. 膨胀：正文承载过多细节

即使内容没有重复，过长的 Skill 也会增加阅读和执行负担。

**改进**：正文保留主流程和少量关键注意事项，将详细案例、排错目录移至参考文件，按需加载，渐进披露。

## 5. 空转：指令没有改变行为

“这很重要”“别省略”“用户很在意准确”等强调，如果没有对应动作，通常难以提供有效指导。

**改进**：逐句检查，删除后 Agent 的行为是否会改变？保留具体动作、判断条件和验收要求，删去无效强调。

## 6. 否定式：禁令多于目标

“主画布比例固定3:4，不要9:16”，反复描述不希望出现的结果，可能削弱目标本身的清晰度。

**改进**：优先直接定义目标。例如写“主画布采用竖版 3:4”，必要的禁止项则保持简短、明确。
